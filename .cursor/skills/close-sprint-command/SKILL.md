# /закрыть-спринт — нумерованные спринты

Источник правды — **номер**, не название. Папка `.docs/sprints/`, файлы `NN-slug.md` (два знака: `01`, `07`). Имя в файле только подсказка.

Пункт из «Исправить» в `AGENTS.md` — не новый спринт. Несколько пунктов одной сессии = один номер, пока пользователь не сказал закрыть.

## Сначала прочитать индекс

Всегда читай `.docs/sprints/README.md`. Оттуда:

- **Закрыт по** — последний закрытый номер
- **Открыт** — текущий номер или `нет`
- **Следующий номер** — куда писать новый файл

Не ищи очередь в `memory-sprint-*.md` и не в `.docs/history/`.

## Когда только читать (не писать)

Пользователь сказал «дальше», «следующий пункт», «что дальше»:

1. Прочитай индекс.
2. Если есть **Открыт: NN** — работай в этом номере, открой `NN-*.md`.
3. Если **Открыт: нет** — следующий срез = **Следующий номер**, файл ещё не создавай.
4. Не создавай `NN+1` и не закрывай спринт.

## Когда писать (`/закрыть-спринт` / «закрой спринт»)

1. Сверь git: ветка, `git status -sb`, какие файлы реально менялись. Секреты (`.env`) в отчёт не клади.
2. **Есть открытый NN** — обнови `.docs/sprints/NN-*.md`, поставь `Статус: закрыт`. В индексе: `Закрыт по: NN`, `Открыт: нет`, `Следующий номер: NN+1` (два знака).
3. **Открытых нет** — создай `Следующий номер` как новый файл, сразу `закрыт`, сдвинь индекс так же.
4. Номер не меняй, не переименовывай старые `NN-*.md`, дырки не оставляй (`05` → `07` нельзя).
5. Slug латиницей, короткий: `07-ui-fixes`. Заголовок файла: `# Спринт 07 — правки UI`.
6. Обнови таблицу в README (статус, ссылка).
7. Закрытые пункты — галочки в `.docs/backlog/README.md`. Новые папки — `STRUCTURE.md`.
8. `AGENTS.md` трогай только если изменился roadmap или путь к спринту.
9. Хук `.cursor/hooks/sprint-folders.js` сам пишет `.docs/sprints/NN-changes.md` (папки, кратко что, ссылки). Не пиши этот файл руками и не копируй его содержимое в отчёт спринта.

В ответ пользователю первой строкой:

`Закрыт спринт NN. Следующий — NN+1.`

или если закрывать было нечего:

`Спринт NN обновлён, всё ещё открыт.` — так не делай: `/закрыть-спринт` всегда закрывает.

## Шаблон файла спринта

```markdown
# Спринт NN — короткое имя

- Статус: закрыт
- Дата: YYYY-MM-DD
- Ветка: feature/...

## Сделано

-

## Файлы

-

## Дальше

- Спринт NN+1 — …
```

## Не делать

- Не писать новые отчёты в `.docs/history/` — это архив.
- Не создавать `memory-sprint-*.md`.
- Не закрывать спринт после каждого пункта «Исправить».
- Не гадать номер: только индекс, иначе спроси.
