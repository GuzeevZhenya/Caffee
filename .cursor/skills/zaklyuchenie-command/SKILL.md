# Команда: /заключение (для проекта кофейни)

Когда пользователь вводит команду `/заключение`, проанализируй текущую сессию
и создай файл отчёта в папке `.docs/history/` с именем
`YYYY-MM-DD_coffee-summary.md` по следующему шаблону:

```markdown
# Итоги сессии: Кофейня — [Краткая тема]

## 📌 Что было сделано

- [ ] Реализованные сценарии бота / фичи / исправления багов.
- [ ] Изменения в логике работы с клиентами или заказами.

## 📂 Измененные файлы и компоненты

- путь/к/файлу — краткое описание изменений (например, обработчики команд, стейт-менеджер, стили).

## 🔌 Интеграции и данные

- Изменения Prisma-схемы, ключей Upstash Redis или API-эндпоинтов (если затрагивались).

## 🚀 Следующие шаги

- Что нужно протестировать (сценарии, edge-кейсы) или внедрить дальше.
```

После создания файла выведи пользователю подтверждение и путь к нему.

## Актуализация карты файлов

Дополнительно проверь, добавлялись ли в этой сессии новые папки или файлы
(или исчезали старые). Если да — обнови корневой файл `STRUCTURE.md`
(карта «что за что отвечает»): добавь описание новых файлов/папок в
соответствующие таблицы разделов и убери описания удалённых. Если структура
не менялась, `STRUCTURE.md` не трогай. В подтверждении укажи, обновлялась ли
карта файлов.
